# Findings on the existing `trust-crm` (not modified by this work)

Read from the code in this repository on 2026-10-23. Items marked ✔ were also confirmed by running them. Severity is my judgement for an internet-reachable deployment holding passport data. **No changes were made to `trust-crm`**; each fix needs your decision.

| # | Severity | Finding | Evidence | Recommended action |
|---|---|---|---|---|
| 1 | **High** | `trust-crm/.env` is **committed to git** (since the very first commit) containing the DB password (12 chars) and `JWT_SECRET` (17 chars, human-readable). `.gitignore` lists `.env`, but the file was added before it. ✔ | `git ls-files` shows `trust-crm/.env`; `git log` first commit `cac5abc` | Treat both secrets as compromised: rotate DB password and JWT secret, `git rm --cached`, purge from history if the repo is/was shared. JWT rotation signs everyone out. |
| 2 | **High** | `sql/rls_policies.sql` **cannot work on plain PostgreSQL**: it enables RLS on 9 tables but every `CREATE POLICY` fails (`schema "auth" does not exist`, Supabase-only). Following the README leaves RLS *enabled with no policies* (default-deny for non-owner roles; ignored for the owner). ✔ | Run against a scratch DB: 9× `ALTER TABLE`, 4× `ERROR: schema "auth" does not exist` | Do not run it outside Supabase. If you do use Supabase, note the Express app connects with one DB role and never sets JWT claims, so these policies would not apply to its queries anyway. Real scoping must live in the application layer. |
| 3 | **High** | `POST /auth/bootstrap-super-admin` is unauthenticated until the first user exists (race/takeover on a fresh deployment). | `routes/auth.js` | Create the first admin with a CLI script (as FIND WAY does) or protect with a one-time env token. |
| 4 | Medium | **User enumeration + no throttling** on login: distinct messages "User not found or inactive" vs "Wrong password"; no rate limit or lockout. | `routes/auth.js:66,71` | Single generic error; per-account/IP throttling. |
| 5 | Medium | **JWTs last 7 days, cannot be revoked, and `is_active` is only checked at login.** A deactivated user keeps access up to a week. Role is trusted from the token. | `middleware/auth.js`, `routes/auth.js` | Short-lived access tokens + server-side session/revocation, or re-check `is_active`/role per request. |
| 6 | Medium | **No record-level authorisation.** Any `candidates:write` user can read/edit every candidate; `Agent`s see all candidates. | `routes/candidates.js`, `middleware/role.js` | Scope by assignment/ownership in queries (as FIND WAY does). |
| 7 | Medium | Invalid/expired token returns **400** instead of 401; 500 responses return raw `err.message` (database error text). | `middleware/auth.js:16`, all routes | Return 401; map errors to generic messages, log details server-side. |
| 8 | Medium | `cors()` wide open; `express.json({limit:'10mb'})`; no rate limiting; no security headers. | `app.js` | Restrict origins, lower limit, add helmet + rate limits. |
| 9 | Medium | Passport numbers stored in clear text; `documents.file_path` is a free-form string with no storage, validation or malware handling. | `sql/schema.sql`, `routes/documents.js` | Encrypt sensitive identifiers; introduce private object storage with signed URLs before real uploads. |
| 10 | Low | Audit logging happens **after** commit (and outside the transaction) in several routes, so a failure leaves a committed change with no audit row; `audit_logs` is not append-only. | `routes/finance.js`, `routes/candidates.js` | Write audit in the same transaction; add an append-only trigger. |
| 11 | Low | Stage endpoint accepts any text for `stage`/`status`; `GET /candidates/all` is unpaginated; only one `visa_applications` per candidate (UNIQUE). | `routes/candidates.js`, schema | Validate against an enum; paginate; consider a per-case table if multiple cases per person are needed. |
| 12 | Low | `Dockerfile` uses `node:18` (end-of-life), runs as root, `npm install` instead of `npm ci`, no health check. | `trust-crm/Dockerfile` | Move to an LTS image, non-root user, `npm ci --omit=dev`. |
| 13 | Info | No migration tooling (`schema.sql` with `IF NOT EXISTS`), no API documentation, notification scheduler duplicates rows only through a UNIQUE constraint. | repo | Introduce versioned migrations before the next schema change. |
| ✓ | Good | Payment posting uses a transaction with `SELECT … FOR UPDATE` and validates the remaining balance; money is `NUMERIC`; soft deletes. | `routes/finance.js` | Keep; add a reversal ledger rather than soft deletes if financial history must be immutable. |

How FIND WAY avoids inheriting these: separate credentials and database, service-account auth with re-login on 400/401, exact-match linking, no reliance on trust-crm authorisation, nothing about trust-crm's data is exposed to FIND WAY users.
